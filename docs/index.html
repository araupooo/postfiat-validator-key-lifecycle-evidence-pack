PostFiat Ledger — Validator Key Lifecycle and Rotation Simulation

A rotation-simulation harness and key-lifecycle documentation for the postfiatd validator set, grounded in the pinned source tree. The harness models the validator-set mechanics in that tree — validation quorum, amendment majority, manifest-based key rotation, and the ML-DSA migration path — and reports the states where signing continuity breaks.

Codebase: postfiatd, commit 0085a1ff885d6a446369cf73a4430f75af22be55 ("Merge pull request #50 from postfiatorg/hotfix/upstream-hardening-1.0.9"). Harness: rotation_sim.py 1.0.0. Method: deterministic simulation (seed 20261113) of the mechanics in the pinned tree only — the ledger was not compiled or run (a full build is not feasible on the audit machine: no Conan, ~1 GB RAM available). See README.md for reproduction steps and assumptions.md for everything the model assumes rather than verifies.

Thresholds

Validation quorum is max(ceil(N × fraction), ceil(N × 0.60)) (ValidatorList::calculateQuorum); the amendment majority is votes > floor(N × fraction) with a 2-week hold (AmendmentTable::computeThreshold / passes / doVoting). postfiatd uses 67/100 for both; upstream rippled uses 80/100 for both (SystemParameters.h:85).

Rotation schedule

Staggered rotation of the 66 validators over 56 simulated days (seed 20261113), in weekly batches of 9, with a 7-day overlap window and 0-day manifest propagation delay. Worst day: 0 validators without a trusted signing key. Quorum met every day under the 67% rule: True; under the 80% rule: True. Per-day state is in results/rotation_schedule.csv.

Stress variant: 2-day propagation delay, no overlap

Same set and seed, run with --propagation-delay-days 2 --overlap-days 0 (results/stress/). Each weekly batch of 9 validators spends 2 days without a network-wide trusted key, so up to 9 validators are without a trusted key on the worst day; quorum is still met every day under both rules (57 signing validators vs quorum 45 at 67%, 53 at 80%).

Mid-rotation failure

One validator's new manifest never propagates and its old key is already superseded: 7 days without a trusted signing key (recovery after 7 days by republishing a working manifest). Quorum still holds under both rules (margins 20 at 67%, 12 at 80%). Fleet variant: quorum breaks when 22 validators fail at once (67%) or 14 (80%).

Compromise sweep

Compromised validators lose their votes (revoked, or voting adversarially). Full sweep in results/compromise_sweep.csv: quorum is reachable while 21 or fewer validators are compromised (67% rule) and breaks at 22; at the 80% rule the figures are 13 / 14. The same break points bound amendment majorities, since the amendment minimum (45) equals the validation quorum (45) at N=66.

Mixed classical / post-quantum network

Old nodes verify only the classical half of a hybrid signature, so a validator that presents no classical signature is unverifiable to them. Old nodes lose quorum once 22 validators are hybrid-only (67% rule) or 14 (80% rule). Dual-signed validators count for old and new nodes alike; only hybrid-only validators shrink the old nodes' verifiable set. Full sweep in results/mixed_network.csv.

Coordinated whole-set rotation

If every validator rotates on the same day, quorum is lost for max(0, propagation_delay - overlap) days: no loss at 0-day delay (minutes-scale propagation, consistent with the 5-minute validator-site refresh); 1 day lost at delay 1 / overlap 0; 2 days at delay 2 / overlap 0; 7 days at delay 7 / overlap 0. A 7-day overlap window absorbs even a 7-day delay. Grid in results/coordinated_rotation.csv.

Model, not measurement. These numbers come from the mechanics in the pinned source tree applied to a validator set of 66 (the count listed by the PostFiat testnet explorer on 2026-11-13). They are not measurements of the live network. The assumptions below state what is verified from source and what is assumed.

Assumptions

  • Validator-set size N=66 is the number of validators listed by the PostFiat testnet explorer on 2026-11-13 (ledger ~8,016,789); it is a snapshot, not a protocol constant, and the set changes as validators join and leave.
  • The model counts a validator as signing only when it has a network-wide trusted signing key. A validator in manifest transition (new manifest published, not yet trusted by all peers) counts as NOT signing — a conservative choice.
  • The pinned code has no dual-signing state: a manifest carries exactly one signing key. The 'overlap window' in the schedule is an operational procedure (publish the new manifest early, activate late), not a protocol feature; see assumptions.md.
  • UNL update propagation is modelled as a single delay in whole days. The code's validator-site refresh is 5 minutes by default, so the baseline delay of 0 days (minutes-scale) is the realistic case; multi-day delays are stress cases.
  • Compromised validators are modelled as losing their votes entirely (revoked or voting adversarially). The model does not simulate double-signing, equivocation detection, or negative-UNL exclusion dynamics.
  • Amendment votes expire 24 hours after a validator's last validation; the model does not simulate vote expiry, because the modelled outages are counted in whole days and any validator offline for a full day has no live vote anyway.
